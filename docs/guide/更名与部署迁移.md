# doolla.ai 部署迁移

SDK 使用 `doolla.ai/sdk`，可选驱动和 Chroma 子模块位于此路径下。通过[源码或团队 Go 代理](Go模块打包与安装.md)安装，命令为 `doolla`、`doolla-db` 和 `doolla-chroma`。SQL Server 的驱动标签为 `doolla_mssql`。

1. 在新部署环境设置 `DOOLLA_DSN`、`DOOLLA_API_KEY` 及所用后端的凭据。匿名网页服务应配置至少 32 字节的固定 `DOOLLA_SESSION_SECRET`，重启时复用同一值。私有配置保存在部署环境。
2. 备份旧的会话目录和结果文件，复制到新配置指定的 `history-dir` 与 `workdir`。历史文件以用户身份隔离；有稳定登录身份的接入方应继续返回相同用户 ID。浏览器使用 `doolla_session`。旧实例使用临时签名密钥时，让需要旧匿名会话的用户继续访问原实例。双实例独立写入会话文件，最终切换前需再核对增量。
3. 对已有 Milvus 集合，保留原嵌入模型、维数和索引。将 `memory-collection` 指向原集合或该集合的新别名，核对行数和检索结果。Premium 适配器须显式设置 `memory-url`。
4. 先用独立端口运行新服务。SSE、轮询和 WebSocket 分别使用 `/api/doolla/v2/chat_sse`、`chat_poll` 和 `chat_websocket`（后两项使用相同路径前缀）。嵌入网页同步改用 `/assets/doolla-components.js` 和 `<doolla-chat>`。
5. 核对聊天、SQL 结果、历史与记忆，再安排调用方切换。示例配置和所有环境变量见[配置参考](配置参考.md)。

2026-11-25 的本机验证使用 18099 端口。Chrome 通过 SSE 查询 MES 的 `dbo.Pro_Mo`，页面表格和最终答复均返回 4104 行，轮询与 WebSocket 另通过完整响应验证。
