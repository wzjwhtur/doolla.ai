# doolla.ai 配置参考

从仓库根目录执行下列命令。首次启动、本地模型准备和 MES 问数示例见[使用指南](使用指南.md)。

## 选择服务程序

| 程序 | 构建要求 | 适用场景 |
| --- | --- | --- |
| `src/doolla/cmd/doolla` | Go 1.25+。使用 SQLite 或嵌入式 Qdrant 需要 CGO 和 C 编译器 | SQLite、HTTP 记忆后端和本地文件索引 |
| `src/doolla/integrations/database/drivers/cmd/doolla-db` | Go 1.26+，按数据库选择构建标签 | PostgreSQL、SQL Server 等可选数据库，支持一次编入多个驱动 |
| `src/doolla/integrations/chromalocal/cmd/doolla-chroma` | Go 1.25+，使用默认嵌入模型时需要 ONNX Runtime 动态库 | 打开本机 Chroma 持久化目录 |

例如，接 PostgreSQL 时，在部署环境中设置 `DOOLLA_DSN`，其格式见下方数据库表。在同一个终端运行以下命令。将 `DOOLLA_MODEL_URL` 和 `DOOLLA_MODEL` 换为本机 Ollama 实例及已安装的模型。

```sh
: "${DOOLLA_DSN:?请先设置 PostgreSQL 的连接串}"
DOOLLA_DATABASE=postgres DOOLLA_PROVIDER=ollama DOOLLA_MODEL=qwen2.5:1.5b \
DOOLLA_MODEL_URL=http://127.0.0.1:11434 \
go -C src/doolla/integrations/database/drivers run -tags doolla_postgres ./cmd/doolla-db
```

## 使用启动配置文件

从 v0.0.3 起，三个服务程序都接受 `-config`。将启动参数写成 YAML 或 JSON 对象，键名使用下表的命令行参数名，去掉开头的短横线。例如，将以下内容保存为 `doolla.yaml`，并填入已有 SQLite 文件的绝对路径、Ollama 的实际端口和已安装的模型名。

```yaml
listen: "127.0.0.1:8000"
database: sqlite
dsn: "/absolute/path/to/warehouse.sqlite"
provider: ollama
model-url: "http://127.0.0.1:11434"
model: "qwen2.5:1.5b"
```

```sh
doolla -config ./doolla.yaml
# 临时更换端口
doolla -config ./doolla.yaml -listen 127.0.0.1:8019
```

从仓库直接运行可用 `go -C src/doolla run ./cmd/doolla -config "$PWD/doolla.yaml"`。配置文件中的相对路径按服务进程的工作目录解析。文件在启动时读取，修改后重启生效。

若连接串含密码，可省略文件中的 `dsn`，通过环境变量 `DOOLLA_DSN` 提供。模型密钥和会话签名密钥分别通过 `DOOLLA_API_KEY` 和 `DOOLLA_SESSION_SECRET` 传入。文件中的字符串按字面值读取，包括 `${...}`。

## 服务参数

同一启动参数的优先级从高到低为：显式命令行参数、配置文件、对应的环境变量、程序默认值。使用 `go -C src/doolla run ./cmd/doolla -help` 查看参数。运行 `go -C` 时，相对路径以切换后的模块目录为基准。持久化目录和数据文件宜使用绝对路径。

| 参数 | 环境变量或默认值 | 用途 |
| --- | --- | --- |
| `-listen` | `127.0.0.1:8000` | HTTP 服务绑定地址 |
| `-provider`、`-model`、`-model-url` | `DOOLLA_PROVIDER`、`DOOLLA_MODEL`、`DOOLLA_MODEL_URL` | 模型协议、名称、服务基址。默认协议为 `mock` |
| `-stream-model`、`-max-output-tokens` | 默认 `true`、`0` | 前者控制模型请求的流式传输。后者为 0 时使用适配器默认输出限制 |
| `-verify-tool-answers` | 默认 `true` | 发布答案前核验查数、记忆等工具回执。保持开启可避免将未经核验的草稿展示给用户。 |
| `-temperature` | `DOOLLA_TEMPERATURE` | 范围 0 至 2，显式填写 0 会传递给支持该设置的模型。Azure 和 OpenAI Chat 在省略时不会发送该字段；已识别的 Azure 推理部署继续忽略该项 |
| `-auto-save-conversations` | 默认 `true` | 每轮对话自动保存历史。设为 `false` 后，依赖历史存储的后续请求无法读取本轮新增消息 |
| `-locale` | 默认 `en`，环境变量 `DOOLLA_LOCALE` | 面向用户的服务和 CLI 默认语言，支持 `en` 和 `zh-CN`。命令行值优先于 YAML/JSON `locale` |
| `-show-progress` | 默认 `true` | 控制 Agent 生成的中间进度组件。结果组件和最终回答仍会发送 |
| `-openai-legacy-max-tokens` | 默认 `false` | 将 Chat Completions 的输出限制字段切换为 `max_tokens`。本地 Ollama 的该协议与 `-max-output-tokens` 配合时使用 |
| `-max-tool-iterations` | 默认 `10` | 单轮问答允许的工具调用轮数 |
| `-database`、`-dsn` | `DOOLLA_DATABASE`、`DOOLLA_DSN` | 默认后端为 `sqlite`。配置 DSN 后，CLI 在监听端口前检查连接，并注册 SQL 和图表工具。DuckDB 也支持空 DSN 的内存模式 |
| `-sqlite-writable` | 默认 `false` | 默认只读打开已有 SQLite 文件。开启后允许创建数据库和写入 |
| `-sql-max-rows` | `DOOLLA_SQL_MAX_ROWS`，默认 `1000` | 每次查询最多保留的完整行数，设置正整数 |
| `-sql-max-bytes` | `DOOLLA_SQL_MAX_BYTES`，默认 `4194304`（4 MiB） | 每次查询最多保留的数据字节，按每格 UTF-8 内容加 1 字节分隔符累计，设置正整数。列名、驱动和输出序列化的开销另计 |
| `-duckdb-init-sql` | `DOOLLA_DUCKDB_INIT_SQL` | 在每个新建的 DuckDB 物理连接上执行，例如 `CREATE TEMP VIEW sales AS SELECT 42 AS total` |
| `-workdir`、`-history-dir` | `DOOLLA_WORKDIR` 默认为 `.doolla`，`DOOLLA_HISTORY_DIR` 默认为空 | 查询 CSV 写入工作目录下的 `files` 用户目录。历史目录用于持久化对话，留空时对话保存在进程内 |
| `-memory` | `DOOLLA_MEMORY`，默认 `local` | Agent 检索和保存记忆的后端 |
| `-embed-url`、`-embed-model` | `DOOLLA_EMBED_URL`、`DOOLLA_EMBED_MODEL` | v0.0.4 起可配置嵌入服务基址和模型 ID。设置基址时需要同时指定模型 |
| `-embed-dim`、`-embed-api-key` | `DOOLLA_EMBED_DIM`、`DOOLLA_EMBED_API_KEY` | 索引向量维数（正整数）和可选的嵌入服务令牌 |
| `-allow-origins` | `DOOLLA_ALLOWED_ORIGINS` | 逗号分隔的可信网页来源，例如 `https://portal.example.com` |
| `-ui-features`、`-replace-ui-features` | 默认沿用内置策略 | 读入界面权限 JSON，例如 `{"tool_names":["analyst"],"public_help":[]}`。空组列表对所有人开放。加 `-replace-ui-features` 时只使用显式配置的权限。可见工具名称（`tool_names`）的用户会在聊天区看到调用失败提示，生成的 SQL 由 `sql_query` 控制（默认 `admin`、`user`），只显示本轮传给内置 SQL 工具的语句。原始数据库错误详情由 `tool_error` 控制（默认仅管理员）。后续重试成功时，先前的提示仍保留在当前对话中 |
| `-audit`、`-audit-ui`、`-audit-response-text` | 均默认 `false` | 启用结构化审计。后两项分别记录界面权限检查、完整模型答复正文 |
| `-log-timings` | 默认 `false` | 输出 `doolla.metric` JSON 日志，用请求 ID 关联首帧、首条回答、模型各轮、工具、记忆召回和会话持久化。也记录重放准入与拒绝次数 |
| `-replay-retention` | 默认 `5m` | 请求完成后保留其 ID 和可重放响应的时间，支持 `30s`、`5m` 等时长 |
| `-replay-max-entries`、`-replay-max-in-flight` | 默认 `4096`、与总量上限相同 | 分别限制去重记录总数和正在执行的请求数。达到任一限制时，新请求返回 `503`，已有请求仍可重试 |
| `-replay-max-bytes`、`-replay-max-response-bytes` | 默认 64 MiB、4 MiB，参数单位为字节 | 限制重放响应占用的内存。超出预算的响应仍发送给原调用者，请求 ID 在保留期内继续去重 |

重放参数可以使用同名 YAML 或 JSON 键，值为 `0` 时使用默认行为。计时日志独立于审计，时长单位为毫秒。SSE 和 WebSocket 的首帧耗时包含服务端写出，轮询的首帧耗时记录服务端产生首个组件的时间。

当用户明确提交一条 `SELECT` 并只要求查询结果，内置服务会在实际执行语句匹配且获得可验证的单值时直接作答，省去模型总结。SQL 仍经过工具权限、参数校验和执行钩子。SDK 宿主可以设置 `AgentConfig.VerifyToolAnswers` 和 `AgentConfig.DirectSQLResult` 启用同一行为。

`DOOLLA_SESSION_SECRET` 用于签名浏览器身份 Cookie，至少 32 字节。复用同一个密钥可使该身份跨重启保持有效。配置 `DOOLLA_ADMIN_TOKEN` 后，服务端客户端可用 `Authorization: Bearer <token>` 访问管理员功能。工具权限由用户组决定，业务行级访问由数据库授权或应用自己的 SQL 执行器实施。模型密钥使用 `DOOLLA_API_KEY` 或下表的厂商变量，与管理员令牌分别配置。

## 模型服务

`-model-url` 填服务基址，适配器会拼接请求路径。模型名称和基址也可使用厂商环境变量。要让模型问数，所选模型需支持工具调用。

| `-provider` | 基址示例或默认值 | 厂商变量 |
| --- | --- | --- |
| `ollama` | 默认 `http://localhost:11434`，要求指定已安装模型名 | `OLLAMA_HOST`、`OLLAMA_MODEL`、可选 `OLLAMA_API_KEY` |
| `openai` | 默认 `https://api.openai.com/v1`，调用 Chat Completions | `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY`、可选 `OPENAI_ORG` |
| `responses` | 与 OpenAI 相同的 `/v1` 基址，调用 Responses API | 与 `openai` 相同 |
| `azureopenai` | 如 `https://RESOURCE.openai.azure.com`。`-model` 填部署名，端点与部署名均需设置 | `AZURE_OPENAI_ENDPOINT`、`AZURE_OPENAI_MODEL`、`AZURE_OPENAI_API_VERSION`。凭据使用 `AZURE_OPENAI_API_KEY` 或 `AZURE_OPENAI_AD_TOKEN` |
| `anthropic` | 默认 `https://api.anthropic.com`，调用 Messages API | `ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL`、`ANTHROPIC_API_KEY` |
| `gemini` | 默认 `https://generativelanguage.googleapis.com/v1beta` | `GEMINI_BASE_URL`、`GEMINI_MODEL`、`GOOGLE_API_KEY` 或 `GEMINI_API_KEY` |
| `mock` | 进程内演示，无端点或凭据 | 用于检查界面和传输流程 |

六种远程协议适配器均已用本机模型验证同步、流式和工具调用。Azure OpenAI 与 Gemini 使用本地兼容网关，厂商生产端点、认证及配额需在实际租户中验证。[模型实测记录](../verification/Go-本地模型验收.md)

## 业务数据库

表中主机、账号、密码和库名均为占位符。可选驱动使用 `doolla_` 加后端名作为编译标签，例如 `-tags 'doolla_postgres doolla_mssql'`。连接串含 `;`、`?` 或 `&` 时，在 shell 中用单引号包住整串。

| `-database` | `DOOLLA_DSN` 格式示例 | 接入说明 |
| --- | --- | --- |
| `sqlite` | `/data/warehouse.sqlite` | 标准程序内置 |
| `duckdb` | `/data/warehouse.duckdb?access_mode=read_only` | 需要 CGO，留空使用内存数据库 |
| `postgres` | `postgres://analyst@db.example:5432/warehouse?sslmode=verify-full` | pgx 驱动 |
| `mysql` | `analyst:PASSWORD@tcp(db.example:3306)/warehouse?parseTime=true` | MySQL TCP 连接 |
| `mssql` | `sqlserver://analyst:PASSWORD@db.example:1433?database=warehouse` | 也接受 pyodbc 的 `Driver={ODBC Driver 18 for SQL Server};Server=...;Database=...;UID=...;PWD=...` 及其 `odbc:` 前缀形式。Go 通过原生 SQL Server 驱动连接 |
| `clickhouse` | `clickhouse://analyst@db.example:9000/warehouse` | ClickHouse 原生 TCP 端口 |
| `hive` | `hive://analyst@db.example:10000/default?auth=NOSASL` 或 `DSN=HiveWarehouse` | `hive://` 选择 HiveServer2 Thrift。ODBC 使用本机配置的驱动与数据源。Unix 构建此标签需要 unixODBC 开发库 |
| `oracle` | `oracle://analyst:PASSWORD@db.example:1521/ORCLPDB1` | 指定 Oracle 服务名 |
| `presto` | `https://analyst@db.example:8443?catalog=hive&schema=default` | PrestoDB 原生连接。MES 的 Trino 请求头适配由专用演示入口提供，启动命令见[使用指南](使用指南.md) |
| `bigquery` | `bigquery://PROJECT/US/DATASET` | 配置项目、区域、数据集及查询身份，可通过 `GOOGLE_APPLICATION_CREDENTIALS` 指定凭据文件 |
| `snowflake` | `analyst:PASSWORD@ACCOUNT/DATABASE/SCHEMA?warehouse=WAREHOUSE` | 配置账号、数据库、schema、计算仓库和查询身份 |

SQLite、DuckDB、PostgreSQL、MySQL、SQL Server、ClickHouse、HiveServer2、Oracle、PrestoDB 已通过真实引擎查询。Hive 的实际连接使用原生 Thrift。BigQuery、Snowflake 和厂商 Hive ODBC 仍需现场环境验收。[数据库逐项记录](../verification/Go-数据库验收.md) · [驱动构建说明](../../src/doolla/integrations/database/README.md)

## 记忆存储

`history-dir` 保存用户对话，`memory` 选择检索工具示例和文本知识的存储。从 v0.0.5 起，下列记忆后端参数均可写入 YAML 或 JSON，或在命令行加 `-` 使用。原有环境变量继续生效。同一参数优先采用命令行值，其次是配置文件、环境变量和程序默认值。

| 配置键 | 环境变量 | 用途 |
| --- | --- | --- |
| `memory-url`、`memory-collection` | `DOOLLA_MEMORY_URL`、`DOOLLA_MEMORY_COLLECTION` | 服务基址及集合、索引或类名 |
| `memory-database`、`memory-api-key` | `DOOLLA_MEMORY_DATABASE`、`DOOLLA_MEMORY_API_KEY` | 服务端数据库及可选凭据 |
| `memory-provision` | `DOOLLA_MEMORY_PROVISION` | 自动创建缺失的索引或集合，默认 `false` |
| `memory-tenant`、`memory-namespace` | `DOOLLA_MEMORY_TENANT`、`DOOLLA_MEMORY_NAMESPACE` | Chroma 租户、Pinecone 命名空间 |
| `memory-control-url`、`memory-region` | `DOOLLA_MEMORY_CONTROL_URL`、`DOOLLA_MEMORY_REGION` | Pinecone 管理端点与建索引区域 |
| `memory-marqo-model`、`memory-organization` | `DOOLLA_MEMORY_MARQO_MODEL`、`DOOLLA_MEMORY_ORGANIZATION` | Marqo 建索引模型、Premium 组织 |
| `faiss-dir`、`faiss-metric` | `DOOLLA_FAISS_DIR`、`DOOLLA_FAISS_METRIC` | FAISS 目录与距离度量 |
| `qdrant-dir`、`chroma-dir` | `DOOLLA_QDRANT_DIR`、`DOOLLA_CHROMA_DIR` | 嵌入式 Qdrant 和原生 Chroma 的本地目录 |

### 记忆召回

从 v0.0.6 起，可以分别调整业务知识和成功工具示例的召回参数。两类阈值的范围均为 0 到 1（含端点），条数为正整数。达到阈值的记录少于上限时，只返回实际匹配的记录。

| YAML 配置键 | 环境变量 | 默认值 | 生效位置 |
| --- | --- | --- | --- |
| `memory-text-limit` | `DOOLLA_MEMORY_TEXT_LIMIT` | `5` | 每轮自动加入系统提示词的文本记忆条数上限 |
| `memory-text-threshold` | `DOOLLA_MEMORY_TEXT_THRESHOLD` | `0.7` | 自动召回文本记忆的最低相似度 |
| `memory-tool-limit` | `DOOLLA_MEMORY_TOOL_LIMIT` | `10` | 检索成功工具示例时的默认条数上限 |
| `memory-tool-threshold` | `DOOLLA_MEMORY_TOOL_THRESHOLD` | `0.7` | 检索成功工具示例时的默认最低相似度 |

```yaml
memory-text-limit: 3
memory-text-threshold: 0.75
memory-tool-limit: 5
memory-tool-threshold: 0.8
```

`search_saved_correct_tool_uses` 的单次调用可通过 `limit` 和 `similarity_threshold` 覆盖工具召回默认值，并可用 `tool_name_filter: "run_sql"` 仅检索 SQL 示例。文本召回独立使用自己的配置。

### 各后端设置

| `-memory` | 端点、路径与关键配置 |
| --- | --- |
| `local` | 默认在进程内保存记忆，重启后清空 |
| `faiss` | `DOOLLA_FAISS_DIR` 默认在工作目录的 `faiss/` 下。度量 `DOOLLA_FAISS_METRIC` 可选 `cosine`（默认）或 `l2`，对应 FlatIP 和 FlatL2 |
| `qdrant` | HTTP 端点如 `http://localhost:6333`。嵌入模式保留空端点，通过 `DOOLLA_QDRANT_DIR` 指定持久化目录。目录留空或取 `:memory:` 使用进程内 SQLite |
| `chroma` | 标准程序连接 Chroma HTTP v2，默认 `http://localhost:8000`。设置 `DOOLLA_EMBED_URL` 与 `DOOLLA_EMBED_MODEL`。可用 `DOOLLA_MEMORY_TENANT`、`DOOLLA_MEMORY_DATABASE` 指定租户和数据库。原生 Chroma 程序使用 `DOOLLA_CHROMA_DIR` 和本地 ONNX 模型，可通过 `CHROMAGO_ONNX_RUNTIME_PATH` 指定动态库路径 |
| `milvus` | REST v2，默认 `http://localhost:19530`，`DOOLLA_MEMORY_DATABASE` 可指定数据库 |
| `weaviate` | 默认 `http://localhost:8080`，类名以大写字母开头，默认 `ToolMemory` |
| `opensearch` | 默认 `http://localhost:9200`，使用 k-NN 索引。AWS 请求签名可经 SDK 的 `memory.Config.HTTPClient` 注入 |
| `marqo` | 默认 `http://localhost:8882`，服务端生成嵌入。新建索引时可用 `DOOLLA_MEMORY_MARQO_MODEL` 选择服务端模型 |
| `azuresearch` | 如 `https://RESOURCE.search.windows.net`，指定索引名及有相应索引权限的 key |
| `pinecone` | 使用已有索引的数据面主机，`DOOLLA_MEMORY_NAMESPACE` 可区分命名空间。创建 serverless 索引时可指定 `DOOLLA_MEMORY_CONTROL_URL` 与 `DOOLLA_MEMORY_REGION` |
| `premium` | 须通过 `DOOLLA_MEMORY_URL` 指定真实服务地址，通过 `DOOLLA_MEMORY_ORGANIZATION` 指定组织。此适配器支持工具使用记忆 |

为支持自动建集合的远程后端设置 `DOOLLA_MEMORY_PROVISION=true` 可创建缺失的索引或集合。此选项默认关闭。Chroma HTTP 需要预先存在的租户和数据库。Chroma 与 Doolla 在同一主机上运行时，应分别分配监听端口。

以下 v0.0.5 的 `doolla.yaml` 示例使用本机 Milvus，并假设嵌入服务提供模型 ID 为 `bge-small-zh-v1.5` 的 512 维模型。请按实际部署替换地址、模型和维数。使用已有集合时，嵌入模型和维数应与写入时一致。

```yaml
memory: milvus
memory-url: "http://127.0.0.1:19535"
memory-collection: "doolla_mes_memory"
memory-provision: true
embed-url: "http://127.0.0.1:9000/v1"
embed-model: "bge-small-zh-v1.5"
embed-dim: 512
# embed-api-key: "替换为嵌入服务的令牌"
```

### SSE 正文预览

聊天组件在请求元数据中发送 `{"answer_deltas":true}`。当模型提供流式文本、服务开启 `stream-model`，且该 Agent 允许直接展示草稿时，SSE 会在原有最终 `text` 事件之前发送 `answer_delta` 事件，`data.text` 是本次追加的纯文本。前端用最终事件替换预览并渲染 Markdown。自建客户端可以只订阅最终事件。

默认 CLI 启用工具回执校验，查数服务应保留这一设置。需要即时正文的普通对话服务可以显式设置 `verify-tool-answers: false`。启用 SQL 记忆人工确认、响应改写、完成回调或自动重试的 Agent 仍会等到完整答案，以免草稿泄露被拦截的内容或重试时出现重复文本。客户端请求不能关闭服务端校验。

### 向量缓存与 SQL 示例确认

| 参数 | 环境变量 | 默认值 | 用途 |
|---|---|---|---|
| `embed-cache-size` | `DOOLLA_EMBED_CACHE_SIZE` | `0` | 每个打开的记忆存储最多缓存多少条成功的模型向量。设为正整数启用进程内 LRU 缓存。 |
| `confirm-sql-memory` | `DOOLLA_CONFIRM_SQL_MEMORY` | `false` | 启用后，模型提交的 SQL 示例须由用户确认后保存。 |

启动日志显示实际向量模式。配置 embedding 服务时使用 `external`；本地词面匹配使用 `lexical`；Chroma 原生模型使用 `native-model`；由后端计算或管理向量的服务显示 `backend-managed`。兼容已有索引的历史散列模式显示 `legacy-md5`，它无法衡量文本的业务语义。切换 embedding 模型时应为新模型重建索引或选择独立集合，因为历史向量和新向量需要处于同一向量空间。缓存按存储实例隔离，容量单位是向量条数，每个缓存向量约占 `4 × 维数` 字节及少量管理开销。

启用确认后，成功返回查询结果的内置 `run_sql` 会向具备 `save_question_tool_args` 权限的用户展示一张卡片，卡片显示原始问题。具备 `sql_query` 展示权限的用户还可查看经过策略变换后实际执行的 SQL，其他用户可根据查询结果确认。点击“确认并保存这条 SQL 示例”会再次检查权限和保存策略。记录包含确认人、原请求 ID、会话 ID 和工具调用 ID；重复确认只保存一份。同一身份只能在原会话内确认，候选保存于本进程内存，15 分钟后失效，最多保留最近 512 条，重启后须重新执行查询。多副本部署需让确认操作回到生成卡片的实例。企业多租户接入见 [Go SDK 接入](Go-SDK接入.md)。
