# doolla.ai 使用指南

[English getting started guide](en/getting-started.md)

Doolla 可以把自然语言问题转换为 SQL，调用数据库，再把查询结果显示为表格并用文字作答。第一次使用可以直接打开已有的 MES 演示，也可以用下面的三条样例数据在自己的电脑上跑通流程。

| 你要做什么 | 从哪里开始 |
| --- | --- |
| 在浏览器里问数或启动自己的第一个实例 | 本页 |
| 把聊天接入现有网页，或从后端调用 HTTP API | [HTTP 与网页接入](HTTP与网页接入.md) |
| 在 Go 服务中创建 Agent、注册工具并接入业务身份 | [Go SDK 接入](Go-SDK接入.md) |
| 更换模型、数据库、记忆存储或配置权限 | [配置参考](配置参考.md) |

## 仓库目录与测试

| 目录 | 内容 |
| --- | --- |
| [src/doolla/](../../src/doolla/) | Go SDK、服务入口 `cmd/doolla`、集成适配器和内嵌网页资源。 |
| [tests/](../../tests/) | SDK 和集成测试。需要访问 Go 包私有成员的测试源码集中在 `tests/_whitebox/`，对应包通过相对符号链接编译这些测试。 |
| [examples/](../../examples/) | 可运行的 Go 示例，包括 MES 问数、模型对比和工具参数绑定。 |

SDK 的导入路径为 `doolla.ai/sdk`。在仓库根目录用 Go 1.26 或以上分别运行以下命令，覆盖 SDK 同包测试、公开接口、示例和默认集成测试。启用可选数据库驱动的命令见[驱动说明](../../src/doolla/integrations/database/README.md)。

```sh
go -C src/doolla test -race ./...
go test -race ./...
```

## 在已有 MES 演示中问第一题

在运行演示的电脑上打开 [MES 聊天页面](http://127.0.0.1:56707/)。这个端口属于本次本地部署。在另一台电脑运行时，使用终端打印的地址。

1. 在输入框中输入 **“MES 中一共有多少条工单记录？又有多少个不同的工单号？工单表是 mes.dbo.pro_mo，工单号字段是 moid。请查询数据库后用中文回答这两个数字。”**
2. 查看 **Query Results** 中的两项计数，再核对中文答复。本次验收快照为 **4,100 条记录、4,100 个不同工单号**。之后以数据库当时的结果为准。有工具名称权限的用户还会在任务栏看到 `Execute run_sql`。
3. 点击表格的 **Export** 可将 CSV 下载到浏览器。如果只看到一段 SQL 或一段文字，先核对有没有 **Query Results**，再引用数字。小模型偶尔会描述它准备执行的 SQL。遇到这种情况，在同一对话发送下面这句话，直接要求执行。

> 请调用 run_sql，在 MES 工单表 mes.dbo.pro_mo 上执行 SELECT COUNT(*) AS total_records, COUNT(DISTINCT moid) AS distinct_moid FROM mes.dbo.pro_mo。请用中文告诉我工单总行数和不同工单号数量。

MES 示例连接只放行对工单表做总数或不同工单号数的聚合。若模型尝试返回工单明细，连接会拒绝该查询。可以重新说明“只返回两个汇总数字”。

## 用 SQLite 和本地模型启动自己的实例

下面的命令从本仓库根目录执行，适用于 macOS 或 Linux。准备 Go 1.25 或以上、C 编译器、`sqlite3` 命令行，以及支持工具调用的 Ollama 模型。Go 二进制已内嵌聊天页面。

### 1. 确认模型端点

本次 MES 演示使用的 Ollama 端口是 `54053`。在同一台电脑复用它时，先设置模型地址。

```sh
export DOOLLA_MODEL_URL=http://127.0.0.1:54053
```

如果使用自己安装的 Ollama，其默认地址为 `http://127.0.0.1:11434`。先启动 Ollama，再用 `ollama pull qwen2.5:1.5b` 准备模型。在下列输出的 `models` 列表中确认有 `qwen2.5:1.5b`。

```sh
model_url="${DOOLLA_MODEL_URL:-http://127.0.0.1:11434}"
curl -fsS "$model_url/api/tags"
```

### 2. 创建样例库并启动服务

保持在同一个终端，创建临时目录并记下打印的路径。下面写入的是独立样例库，Doolla 启动后以只读方式打开它。

```sh
demo_dir="$(mktemp -d)"
echo "$demo_dir"
sqlite3 "$demo_dir/production.sqlite" <<'SQL'
CREATE TABLE production (line TEXT, good_units INTEGER);
INSERT INTO production VALUES ('A', 12), ('A', 8), ('B', 15);
SQL

go -C src/doolla build -o "$demo_dir/doolla" ./cmd/doolla
"$demo_dir/doolla" -listen 127.0.0.1:8018 \
  -provider ollama -model qwen2.5:1.5b -model-url "$model_url" \
  -database sqlite -dsn "$demo_dir/production.sqlite" \
  -workdir "$demo_dir/work" -history-dir "$demo_dir/history"
```

看到 `Doolla listening on http://127.0.0.1:8018` 后，保持服务终端打开。需要停止这个实例时，在该终端按 `Ctrl+C`。

### 3. 核对查询结果

打开 [SQLite 示例页面](http://127.0.0.1:8018/)。第一次查询可直接给出 SQL，确认工具确实取到了数据。输入 **“请调用 run_sql 执行 SELECT line, SUM(good_units) AS total_good_units FROM production GROUP BY line ORDER BY line ASC。请按返回的顺序，用中文告诉我每条产线的合格数量。”** 结果表应有两行。

| 产线 | 合格数量 |
| --- | ---: |
| A | 20 |
| B | 15 |

服务会把非空查询结果保存在 `$demo_dir/work/files/` 内的用户子目录。输入“查询各条产线的合格数量，并绘制柱状图”即可在同一轮完成查询和绘图。本轮只有一个结果时，`visualize_data` 自动使用它。有多个结果时，工具通过 `result_id` 选择其中一个。也可以通过 `filename` 指定当前用户目录中已有的 CSV。

`sql-max-rows` 或 `sql-max-bytes` 达到上限且仍有未返回的数据时，结果表、模型回执和 CSV 都只保留能放下的完整行。界面会说明已截断和预览行数。要获得准确总数，请单独执行 `COUNT(*)`。按分类统计完整数据时，请用 SQL 的 `GROUP BY` 和 `COUNT(*)`，再用聚合结果绘图。

结果只有一列分类（例如工单状态）时，默认图表按分类值计数，忽略 CSV 中的空值，并按分类名排序。使用本轮截断的查询结果绘图时，图表回执会标记预览范围。

同一浏览器使用签名 Cookie 保持身份。需要重启后延续身份时，从首次启动起设置固定的 `DOOLLA_SESSION_SECRET`（至少 32 字节），并复用相同的历史和工作目录。

## 从源码另起一个 MES 实例

这条路径适用于已有本机 Trino 协调器、其中已挂载 `mes` catalog 且能读取 `dbo.pro_mo` 的环境，还需要 Go 1.26 或以上。模型名及两个端点应与当前部署一致。以下示例让新实例监听 `8019`。

```sh
go run -tags doolla_presto ./examples/mes \
  -trino-url http://127.0.0.1:18080 \
  -model-url "${DOOLLA_MODEL_URL:-http://127.0.0.1:11434}" -model qwen2.5:1.5b \
  -listen 127.0.0.1:8019 -stream-model=false -workdir "$(mktemp -d)" -audit
```

打开 [新 MES 实例](http://127.0.0.1:8019/) 并输入本页第一题。终端中的 `Trino query_id` 可用于在协调器中核对执行情况。这个示例的端点参数使用回环 IP 和明确端口。接其他业务库时按对应驱动配置 DSN。[数据库接入配置](配置参考.md)

## 遇到问题时先查哪里

| 现象 | 检查方法 |
| --- | --- |
| 页面打不开或提示端口被占用 | 使用当前进程打印的地址。示例端口被占用时，修改 `-listen` 后再打开新地址。 |
| 页面能打开，模型没有作答 | 查看服务终端日志。访问模型端点的 `/api/tags` 检查地址和模型名。`/health` 只表示 Go HTTP 服务正在运行。 |
| 只有欢迎语或演示文字 | 运行参数中选择 `-provider ollama`，并提供 `-dsn`。CLI 的默认模型为 `mock`。 |
| 没有结果表或 SQL 报错 | 先检查库名、表名、字段名和数据库账号权限。SQLite 示例使用已存在文件的绝对路径，MES 示例只接受约定的聚合。 |
| 操作返回 Access Denied | 普通用户可用 `/help` 查看帮助。管理员命令或受限工具需要对应的用户组。[身份接入](Go-SDK接入.md) |
